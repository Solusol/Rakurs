# Облако «Ракурса»: настройка Supabase

Истории хранятся в браузере, как и раньше. После входа в облако их копия сохраняется
в Supabase и подтягивается на других устройствах под тем же аккаунтом.

## Один раз

1. Зарегистрируйся на https://supabase.com и создай проект (регион — любой европейский).
2. В проекте открой **SQL Editor → New query**, вставь содержимое `schema.sql` и нажми **Run**.
3. **Authentication → URL Configuration**: в поле *Site URL* укажи адрес приложения,
   например `https://solusol.github.io/Rakurs/`. Туда же добавь его в *Redirect URLs*.
4. Там же, **Authentication → Sign In / Providers → Email**: при желании выключи
   *Confirm email* — тогда вход работает сразу, без письма с подтверждением.
5. **Project Settings → API Keys**: скопируй *Project URL* и ключ **anon / publishable**.
   Ключ **service_role** никуда не вставлять — он даёт полный доступ к базе.
6. Впиши URL и ключ в `cloud-config.js` и отправь изменения в репозиторий.

## Как это работает

- `cloud.js` загружается до `app.js`. При входе он сверяет истории в браузере с облаком,
  забирает более новые, отправляет недостающие, затем запускает приложение.
- Каждое сохранение (`flush`) отправляется в облако через 1–2 секунды.
- Раз в минуту и при возвращении на вкладку проверяются обновления с других устройств.
- Если в облаке оказалась версия, которой это устройство не видело, она сохраняется
  отдельной историей «… (с другого устройства)». Ничего не затирается.
- Доступ к строкам ограничен RLS: пользователь видит только свои данные.

## Файлы

- `schema.sql` — таблицы `rk_projects`, `rk_meta`, политики RLS.
- `../cloud.js` — синхронизация и окно входа.
- `../cloud-config.js` — адрес проекта и публичный ключ.
- `../supabase.js` — библиотека supabase-js (UMD), лежит в репозитории, чтобы работать без CDN.
